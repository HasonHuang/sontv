# IPTV Proxy 订阅接入入门

> **你的情况**：你有一份或多份 M3U 订阅。你希望流量经过自己的服务器（反向代理）。然后把订阅地址填入播放器。
>
> 本文的执行时间约 15 分钟。
>
> ⚠️ **面板的「订阅聚合」功能不做反向代理。** 该功能只合并订阅，并保留上游地址。
> 「M3U 导入」功能提供反向代理。参见开头的对比表和第 6 步。

---

## 先看这里：两种导入方式的区别

面板提供两个导入功能。请根据目标选择。

| 项目 | **M3U 导入** | **订阅聚合** |
| --- | --- | --- |
| **输出地址** | ✅ **代理地址** | ❌ **上游原始地址** |
| 适用目标 | 流量经过自己的服务器 | 合并多份订阅 |
| 频道存储 | 保存到你的分组 | 不保存。生成总订阅时拼接 |
| 上游修改后 | **需要重新导入** | **自动更新** |
| 删除单个频道 | 支持 | 不支持 |
| 工作模式 / 缓存 / 录制 / Token | ✅ 支持 | ❌ 不支持 |

> ⚠️ **实测结果（2026-10-02）**：订阅聚合的频道在 `/playlist.m3u` 中输出**上游原始地址**。
> 手动添加的频道输出 `http://localhost:19899/mygroup/HOY77.m3u8`。
> 订阅聚合的频道输出 `https://上游域名/...`。
> **因此订阅聚合不等于反向代理。**

> ⚠️ **M3U 导入不接受订阅地址。** 该窗口只接受粘贴内容和上传文件。
> 「订阅聚合」页接受订阅地址，但不做反向代理。
>
> 导入订阅前，先获取订阅内容。参见第 2 步。

**选择建议**：需要反向代理时，选择 **M3U 导入**。该功能把订阅转换为你的频道，并支持代理、删除和模式更改。

多份订阅：**对每份订阅分别执行一次导入**。每份订阅生成一个独立的分组。总订阅地址包含全部分组，全部经过代理。

---

## 三分钟速通

执行下列五步可以完成安装。

1. **安装** —— 选择 `1`，按回车键接受默认值
2. **登录** —— 打开 `http://服务器IP:19899/panel`，使用 `admin` / `admin`
3. **导入** —— 分组管理 → M3U 导入 → 粘贴订阅内容或上传文件 → 频道模式 **Proxy** → 导入策略 **追加** → 开始导入
4. **复制地址** —— 分组管理 → 复制订阅地址。每个分组各有一条
5. **填写地址** —— 在播放器中填写该地址

总订阅地址包含全部分组：`http://服务器IP:19899/playlist.m3u`

完成上述步骤后，阅读后续章节了解细节。

## 第 1 步：安装

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YanG-1989/rust/main/IPTV%20Proxy/iptv-proxy.sh))
```

选择 `1` 开始安装。安装程序询问四个问题。按回车键接受默认值。

| 问题 | 默认值 |
| --- | --- |
| 面板端口 | `19899` |
| 面板账号 | `admin` |
| 面板密码 | `admin` |

安装目录是 `/opt/iptv-proxy`。服务自动设置为开机自启。
在浏览器中打开 `http://服务器IP:19899/panel`，使用 `admin` / `admin` 登录。

> ⚠️ **两件马上要做的事**
> 1. **更改密码** —— 执行 `iptv-proxy pass 你的新密码`。改完后需要重新登录
> 2. **放行端口** —— 面板默认监听所有网卡。在云安全组和防火墙中放行 19899

## 第 2 步：把你的订阅导进来

打开 **分组管理**，点击顶部的 **M3U 导入**。

**该窗口只包含「选择文件」和「M3U 文本」两个输入框。窗口内没有订阅地址输入框。** 请先获取订阅内容。

### 获取订阅内容

| 方式 | 操作 |
| --- | --- |
| **下载文件** | 在浏览器中打开订阅地址。选择「另存为」，保存为 `.m3u` 文件 |
| **复制内容** | 在浏览器中打开订阅地址。选择全部内容并复制 |

> 订阅地址返回一份文本文件。第一行是 `#EXTM3U`。内容较多时，下载文件更方便。

### 执行导入

| 输入项 | 内容 |
| --- | --- |
| 选择文件 / M3U 文本 | 上一步获取的文件或内容。二选一 |
| 频道模式 | **Proxy** |
| 导入策略 | **追加** |

点击「开始导入」。等待数秒。频道显示在分组列表中。

> **需要自动更新时：** 使用「订阅聚合」页。该页接受订阅地址，但不做反向代理。参见开头的对比表。

### 频道模式怎么选

| 选项 | 使用条件 |
| --- | --- |
| **Proxy** | **默认选择**。支持缓存、回看、录制 |
| Rewrite | 只改写播放列表地址。出网流量为零。不支持缓存 |
| Redirect | 返回 302 跳转。出网流量为零。源地址对播放器可见 |
| DASH | 订阅是 `.mpd` 格式 |
| Passthrough | 完全信任源地址 |

不确定时选择 **Proxy**。导入后可以更改。

### 导入策略

| 策略 | 行为 |
| --- | --- |
| **追加** | 跳过同名分组。新分组追加到列表。**推荐** |
| 合并 | 保留同名分组。新频道加入该分组 |
| 覆盖 | 用新数据替换同名分组的全部内容 |

### 导入后会自动处理的东西

导入程序自动完成下列处理：

- 频道名称、`tvg-id`、分组标题等元数据**全部保留**
- UA / Referer / Origin 等请求头**自动抓取**
- 源站地址里的相对路径**自动补全**

> ⚠️ **部分频道导入后无法播放。** 部分源站校验 Referer 等请求头。参见第 5 步。

## 第 3 步：拿到订阅地址

### 单个分组地址

在分组列表中，点击分组右侧的**复制按钮**。

```
http://你的IP:19899/分组ID/playlist.m3u
```

### 总订阅地址

该地址包含全部分组。多份订阅导入后使用该地址。

```
http://你的IP:19899/playlist.m3u
```

> 访问范围设为「隐藏」的分组不出现在总订阅中。该分组的独立地址仍然可以访问。

## 第 4 步：自定义顺序

面板支持三种排序方式。各自的可调整范围不同。

| 排序对象 | 支持调整 | 操作方式 |
| --- | --- | --- |
| **分组内的频道** | ✅ | 展开分组，拖动频道 |
| **订阅源的优先级** | ✅ | 在订阅聚合页点击 **↑ / ↓** 按钮 |
| **分组之间的顺序** | ❌ | 面板未提供该功能 |

> **顺序决定优先级。** 订阅聚合中靠前的源优先采用。多个源提供同名频道时，靠前的源生效。

## 第 5 步：让频道真的能播

导入后尝试播放频道。无法播放时，按下列顺序检查。

### 检查源地址

在 VLC 中打开**原始订阅地址**。可以播放则源地址正常。无法播放则源站故障。IPTV Proxy 无法处理源站故障。

### 检查工作模式

打开「分组管理」编辑分组，选择「工作模式」。

| 源的类型 | 工作模式 |
| --- | --- |
| `.m3u8`（HLS） | Proxy / Rewrite / Redirect |
| `.mpd`（MPEG-DASH） | **DASH** |
| `.flv` / `.ts` 连续流 | **Remux** |

工作模式与源类型不匹配时，频道无法播放。

### 添加 UA 和 Referer

部分源站校验请求头。这是导入后无法播放的常见原因。

编辑分组或频道，打开「网络配置」。

| 字段 | 填写条件 | 示例值 |
| --- | --- | --- |
| **User-Agent** | 源返回 403 或错误页面时 | `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36` |
| **自定义请求头** | 源校验 Referer 时 | 点击「＋ 添加请求头」，每行一条，例如 `Referer: https://源站域名/` |

> 在分组中填写，该分组的全部频道生效。在频道中填写，只对该频道生效。留空则继承分组的设置。

## 第 6 步：让订阅自动更新（不反代）

> ⚠️ **本节的功能不提供反向代理。** 阅读后再执行。
>
> 订阅聚合的频道在总订阅中**保留上游原始地址**。播放器直接连接源站。流量不经过服务器。
> 因此无法使用 Token、缓存和录制，也无法隐藏源地址。
>
> | 目标 | 功能 |
> | --- | --- |
> | 流量经过服务器，支持缓存、录制、防盗链 | **M3U 导入**（第 2 步） |
> | 合并多份订阅，接受源地址可见 | 订阅聚合（本节） |
>
> **需要对两份订阅使用代理时：** 对每份订阅分别执行一次 M3U 导入。
> 每份订阅生成一个独立的分组。总订阅地址包含全部分组，全部经过代理。
> 上游修改后，需要重新导入。

仅需要合并功能时，执行本节。

打开左侧导航的 **订阅聚合**，点击 `+ 添加订阅源`，填写下列内容。

| 字段 | 内容 |
| --- | --- |
| 订阅源名称 | 用于识别的名称 |
| 订阅地址 | M3U 订阅地址。**该字段接受地址，M3U 导入不接受** |
| 启用 | 可先设为「停用」以检查结果 |
| 缓存（分钟） | 重新获取上游的间隔。`60` 表示 1 小时 |
| **只要这些（include）** | 留空则导入全部频道。填写后只导入名称匹配的频道 |
| **剔除这些（exclude）** | 填写后不导入名称匹配的频道 |

### 过滤频道

订阅聚合页提供频道过滤功能。示例：

```
只要这些（include）：
央视
卫视

剔除这些（exclude）：
购物
测试
```

单个订阅源的 include 和 exclude **按频道名称匹配**。匹配时不区分大小写。名称包含关键字即匹配。

`group:` / `id:` / 正则语法只适用于「全局排除」。单个订阅源不支持这些语法。

### 全局排除

该设置对全部订阅源生效。点击「全局设置 ▶」展开。

| 配置 | 说明 |
| --- | --- |
| **合并位置** | 置底（默认）或置顶。决定聚合频道在分组内的排列位置 |
| **默认缓存（分钟）** | 新建订阅源的默认缓存时长 |
| **全局排除** | 对全部订阅源生效的排除列表，每行一条 |

全局排除支持以下语法。

| 语法 | 匹配对象 | 示例 |
| --- | --- | --- |
| 关键字 | 频道名称 | `购物` |
| `group:` 前缀 | 分组名称 | `group:成人` |
| `id:` 前缀 | tvg-id | `id:XXX.com` |
| `/正则/` | 频道名称正则 | `/^广告/` |

### 分组整理

每个订阅源提供「分组处理」设置。三选一。

| 模式 | 效果 |
| --- | --- |
| **各自保留原名** | 输出保留上游的分组名称 |
| **逐个指定** | 逐个指定输出的分组名称 |
| **全部合并到一个组** | 全部上游分组使用同一个分组名称 |

点击 **保存订阅配置** 保存设置。点击 **预览** 可以查看合并结果。

## 第 7 步：功能之间的关系

前面几节提供了最短执行路径。本节说明各功能之间的关系。

### 频道的来源和归属

**两条路，结局完全不同**：

```
   M3U 导入（粘内容/传文件）          订阅聚合（填订阅地址）
            │                                │
            ▼                                ▼
      变成你的分组里的频道            不落地，生成总订阅时
            │                        直接拼上游的内容
            ▼                                │
      ┌─────────────┐                        │
      │   分 组     │                        │
      └──────┬──────┘                        │
             │ 分组决定                      │
   ┌─────────┼─────────┐                     │
   ▼         ▼         ▼                     ▼
工作模式  访问范围  网络配置            上游原始地址
（怎么转）（进不进）（UA/代理）        ⚠️ 不经过你的服务器
   │
   ▼
http://你的IP:19899/分组/频道.m3u8   ✅ 走代理
```

**关键事实：工作模式、访问范围和 UA 属于分组，不属于频道。**

因此：**只有 M3U 导入的频道具有代理地址。** 订阅聚合的频道没有分组归属。
这些频道无法读取已设置的 Proxy 模式，在总订阅中保持上游原样。

> 该区别在输出中可见。手动添加的频道输出 `group-title="我的组"`（显示名称）。
> 订阅聚合的频道输出 `group-title="july"`（分组 ID）。二者走不同的代码路径。

### 分组管理与订阅聚合的关系

「分组处理」决定**总订阅中频道的排列和分组名称**。该设置**不改变代理规则**。

| 模式 | 效果 | 使用条件 |
| --- | --- | --- |
| **各自保留原名** | 输出保留上游分组名称 | 上游分组名称清晰 |
| **逐个指定** | 逐个指定输出的分组名称 | 上游分组名称无意义，需要整理 |
| **全部合并到一个组** | 全部上游分组使用同一名称 | 需要平铺的列表 |

**「逐个指定」的使用方法**：先点击 **读取分组** 获取上游的分组列表。面板显示分组清单。逐个填写输出名称。

> 面板提示：「点『读取分组』先抓一次——不看清楚源里有什么，配出来的规则就是盲配。」

> ⚠️ **这里填写的名称只是输出时的分组标题。** 该设置不启用代理。
> 实测填写 `july` 后，输出地址仍为上游原始地址。

### 顺序、优先级与合并位置

| 目标 | 设置位置 |
| --- | --- |
| 调整订阅源的优先级 | 订阅聚合页的 **↑ / ↓** 按钮。靠前的源优先 |
| 调整聚合频道在分组内的位置 | 全局设置 → **合并位置**。置顶或置底，默认置底 |
| 调整分组内频道的顺序 | 分组管理页拖动频道 |
| 调整分组之间的顺序 | 面板未提供该功能 |

### 访问范围与总订阅

每个分组提供四种访问范围。该设置决定分组是否出现在总订阅中。

| 访问范围 | 出现在 `/playlist.m3u` | 独立地址可播放 | 用途 |
| --- | --- | --- | --- |
| **公开** | ✅ | ✅ | 正常分发 |
| **隐藏** | ❌ | ✅ | 向指定人员分发独立地址 |
| **归档** | ❌ | ❌ 整组停用 | 暂时下架。EPG 和台标匹配继续执行 |
| **免验证** | ✅ | ✅ | 不校验 Token 的公开入口 |

> **该设置只作用于 M3U 导入的频道。** 订阅聚合的频道没有分组归属，因此不受访问范围控制。
> 这些频道始终出现在总订阅中，也无法设为「隐藏」或「免验证」。

### 工作模式与录制、回看、预载

以下功能受工作模式限制。

> **本表只适用于 M3U 导入的频道。** 订阅聚合的频道没有工作模式，始终使用上游地址。表中的功能对该类频道无效。

| 功能 | Proxy | Remux | DASH | Rewrite | Redirect | Passthrough |
| --- | --- | --- | --- | --- | --- | --- |
| 本地回看 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 定时录制 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 切片预载（加速起播） | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 缓存加速 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 隐藏源地址 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| 套用 Token | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |

> **录制前必须安装 ffmpeg。** 否则录制任务失败。执行 `apt install ffmpeg`，然后重启服务。

### Token 与地址分发

在「安全管控」页启用以下两项设置。两项设置同时生效。

| 设置 | 功能 |
| --- | --- |
| **启用 Token 验证** | 播放地址必须包含 Token 参数 |
| **随机频道 ID** | 频道 ID 替换为 6 位随机字符。Token 轮换时同步更新 |

**仅启用 Token 验证不足以保护地址。** 真实频道 ID 仍会出现在外部。
两项设置同时启用后，即使他人获得链接也无法播放。

> ⚠️ **启用前先分发地址。** 启用后旧地址全部失效。
>
> 需要免登录入口时，将该分组设为**免验证**。

### EPG × tvg-id

节目单匹配失败的主要原因是 `tvg-id` 缺失或填写错误。

| 环节 | 位置 |
| --- | --- |
| 频道的 tvg-id | 分组管理 → 编辑频道 |
| EPG 总开关 | 节目指南页。**关闭时 `/epg.xml.gz` 返回 404** |
| 检查匹配结果 | 节目指南 → 频道匹配，查看「未匹配」数量 |
| 名称匹配 | 系统设置中可启用。tvg-id 不匹配时按频道名称再匹配一次 |

**M3U 导入保留 tvg-id。** 订阅聚合的 tvg-id 取决于上游提供的值。上游提供错误值时，匹配同样失败。

### 台标与频道

「台标管理」页上传的图标自动匹配频道。匹配成功后，该图标用于 M3U 的 `tvg-logo` 和 EPG 的 `icon`。

- 频道填写了**外部 Logo URL** 时，仍使用外部图床。该图床停止服务后图标无法显示
- 台标页列出缺少台标的频道。按列表补充
- 不建议在频道中填写外部图床。使用台标管理存储在本地

### 监控与频道数量

「系统设置 → 监控」的健康探测**每轮都产生上游请求**。

| 频道数量 | 探测周期 |
| --- | --- |
| 数十个 | 使用默认值 |
| 数百个 | 设置为 15 分钟以上 |
| 仅需要分组页的状态显示 | 关闭该功能 |

在线人数和「频道热度」页的数据来自**访问统计**。该功能需要单独启用。

## 第 8 步：验证结果

执行下列检查。

| 检查项 | 操作 | 预期结果 |
| --- | --- | --- |
| **订阅可访问** | 浏览器打开 `http://你的IP:19899/playlist.m3u` | 显示以 `#EXTM3U` 开头的频道列表 |
| **地址可播放** | 从列表复制一条播放地址，在 VLC 中打开 | 可以播放 |
| **节目单可用**（可选） | 打开 `http://你的IP:19899/epg.xml.gz` | 下载到 XML 文件 |

节目单需要额外配置。打开 **节目指南** 页启用总开关，执行一次采集。然后检查频道的 `tvg-id`。

## 排错

| 现象 | 怎么办 |
| --- | --- |
| 面板打不开 | 端口放行了吗 → `iptv-proxy log` 看日志 → `iptv-proxy url` 确认地址 |
| 订阅地址 404 | 分组访问范围是不是设成了「隐藏」？ |
| 订阅能拉但频道播不了 | 源本身能播吗 → 模式选对吗 → UA / Referer 填了吗 |
| 播放中出现卡顿 | 关闭「系统设置 → 缓存配置」的**预载**，然后重启服务 |
| 内存持续增长 | 缓存后端改为 `memory` 并设置上限。关闭预载 |
| 日志提示缺少 ffmpeg 或 python3 | **警告，不影响播放。** 录制和 EPG 脚本源需要该组件：`apt install ffmpeg python3`，然后重启服务 |
| 频道数量多导致面板变慢 | 在「系统设置 → 监控」中关闭健康探测，或延长探测周期 |

### 常见问题

**Q：更改设置后没有生效？**
点击「保存设置」。热重载关闭时，执行 `iptv-proxy restart`。
下列三个开关在启动时读取，修改后必须重启服务：DASH 会话预启动、配置文件热重载监视、登录失败计数清理。
其余设置即时生效。

**Q：播放器无法打开订阅地址？**
按顺序检查。
① 启用 Token 验证时，地址必须包含 Token 参数。使用面板的「导出全部」获取地址，不要手工拼接
② 频道的访问范围是否设为「隐藏」或「归档」
③ 自己的 IP 是否在封禁列表中。检查安全管控页
④ Token 是否过期

**Q：频道可以播放，但没有节目单？**
检查 EPG 总开关。检查频道的 `tvg-id`。在「节目指南 → 频道匹配」查看「未匹配」数量。

**Q：定时录制任务失败？**
原因是缺少 ffmpeg。面板的「视频素材」页显示检测结果。安装后重启服务。

**Q：日志显示「边缘来源校验模式: Off」？**
该消息表示启用了边缘模式，但未配置密钥或未接受边缘请求。非 CDN 环境下该消息不影响使用。

**Q：启用 Token 后旧地址是否有效？**
旧地址全部失效。**启用前先分发地址。** 启用后需要重新复制地址。

**Q：为什么订阅聚合的频道不是代理地址？**
这是设计行为。订阅聚合只执行合并，不改写地址。使用 M3U 导入实现反向代理。参见开头的对比表。

**Q：如何查看资源占用？**
面板「概览」显示实时指标。**v0.8.2 的回源流量统计失效，数值始终为 0。**
使用 `docker stats` 查看真实数据。参见 [资源占用实测](resource.md)。

## 命令速查

| 命令 | 作用 |
| --- | --- |
| `iptv-proxy pass <新密码>` | 更改密码。该命令可重置忘记的密码 |
