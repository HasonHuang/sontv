# 工作模式 · DASH 转封装

> 模式标识：`dash`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：把 MPEG-DASH（`.mpd` + `.m4s` 分片）实时转封装成 HLS，让只吃 HLS 的播放器也能播。支持 ClearKey 解密。

> 面板的官方说明：「DASH MPD 转封装为 HLS,可选 CENC ClearKey 解密。仅用于 .mpd 源。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy  ──拉流──▶  上游（.mpd 清单 + .m4s 分片）
   ▲                    │
   └──HLS 切片回传──────┘
        （MPD → HLS 实时转封装；支持 ClearKey 解密）
```

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| 源是 **MPEG-DASH** | 地址以 `.mpd` 结尾 |
| 需要**给 HLS 播放器**播放 | 大量电视端和手机播放器只吃 HLS，DASH 源直连播不了 |
| 源用了 **ClearKey 加密** | 自动解密，这是 DASH 模式的主要卖点 |
| 需要**多 CDN 故障切换** | 自动的，不需要配 |

---

## 不适用场景

- 源是 HLS（`.m3u8`）→ 用 [Proxy](mode-proxy.md)，**别给 DASH 模式喂 HLS 源**
- 源是 FLV / TS → 用 [Remux](mode-remux.md)
- 怕配置复杂 → DASH 的调优项多，虽然默认值适配大多数源

---

## DASH 模式自动化了什么

面板原文明确说明，这些**不需要你配置**：

- **304 增量刷新**——上游清单没变就跳过重新解析
- **多 CDN 故障切换**——主 CDN 挂了自动切备用
- **防断流备份**——上游意外断开时的兜底
- **片段级容错**——个别分片损坏不影响整体

真正要你动的是下面的高级参数，而面板的建议是：**不确定用途就不要改，改错会直接影响起播与卡顿。**

## 本模式的全部配置项

通用字段见 **[通用配置项详解](fields-common.md)**。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「DASH（MPD → HLS 转封装）」 | — |
| 内容格式 | **不显示**——DASH 输出固定是 HLS，没有得选 |
| 网络配置（UA / 代理 / 请求头） | **会显示**，DASH 同样要回源，源站要 Referer 时照样得填 |

> DASH 分组**没有「内容格式」下拉框**。选了 DASH 模式就意味着上游是 `.mpd`，输出是 `.m3u8`，不需要你选。

---

### 频道级 · ClearKey 解密

**只有 DASH 模式、分组格式为 MPD、或 Passthrough 带密钥时，这块才显示。**

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **ClearKey 解密密钥** | 源是 ClearKey 加密时才填，**无加密流留空** | 见下方格式 |

**格式**：`kid_hex:key_hex`，**多个密钥每行一对**，KID 和 KEY 都是 **32 位十六进制**。

**例子**（单密钥）：
```
a1b2c3d4e5f60718293a4b5c6d7e8f90:00112233445566778899aabbccddeeff
```

**例子**（多密钥，拖动清晰度时会用不同密钥）：
```
a1b2c3d4e5f60718293a4b5c6d7e8f90:00112233445566778899aabbccddeeff
b1c2d3e4f50617283940a1b2c3d4e5f60:112233445566778899aabbccddeeff00
```

> **Widevine 等其它加密类型不在这里配**，需要手动处理。M3U 导入时 ClearKey 会自动填进这个字段。

---

### 频道级 · 回看保留

DASH 频道支持本地录制，和 Proxy / Remux 一样：

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **回看保留时长** | 想回看多久就填多少小时。留空 = 不录 | `24` |
| **最大磁盘占用** | 怕磁盘被撑爆就设上限，填 `0` = 不限 | `100` |
| **时间偏移** | 回看开头对不上节目时调 | 偏 5 分钟 → `300` |

> **磁盘占用估算：一个 1080p 频道大约每小时 1~2 GB。**

---

### 频道级 · URL 池

**解决 CDN 单连接限流的问题。** 默认关闭，需要时才开。

| 字段 | 说明 | 范围 |
| --- | --- | --- |
| **池大小** | 用几个 token 错峰拉切片 | **2 ~ 6，默认 3** |

**它怎么工作**：视频固定用 `pool[0]`，音频和字幕在 `pool[1..]` 之间轮询，这样单个连接上的请求压力被摊薄。

**什么时候开**：源站限流（大量观众同时看同一个频道时开始花屏/缓冲），或者切片下载频繁 403。

> ⚠️ **有封号风险**：部分视频平台会把多 token 并发判定为**多设备登录**并封号。开之前确认你的源不是这类平台的账号。

## DASH 调优（系统设置 → DASH 调优）

**面板的明确建议：这三组参数默认值已适配绝大多数源，不确定用途就不要改——改错会直接影响起播与卡顿。**

下面按组列出每一项的含义，**只在遇到具体症状时才动对应那一个**。

### 播放体验（影响延迟、起播速度、卡顿稳定性）

| 配置项 | 它做什么 | 什么时候动 | 例子 |
| --- | --- | --- | --- |
| **抗卡缓冲** | 切片打包好之后先压住几秒再发给播放器，**用延迟换稳定**。填 `0` = 关闭，最低延迟 | 频繁卡顿、且能接受延迟变大时，往上调几秒 | 卡得厉害 → `3`；不能容忍延迟 → `0` |
| **防断流备份** | 比实际需要**多拉几段备用**，上游丢片时顶上。**对客户端不增加延迟** | 上游经常掉片、断流 | `2`~`3` |
| **playlist 最少** | 发给播放器的清单里**至少要有多少秒的内容**。太短的话播放器一拖进度条就越界 | 播放器拖进度条时列表空白或报错 | `30`~`60` |
| **快速起播窗口** | 刚连上时从**靠近直播边缘**的位置起播，缩短等待。填 `0` = 关闭，按正常位置起播 | 起播慢，但延迟要求不高 | `10`~`20` |
| **广告空洞裁剪** | 上游插广告会留下时间轴空洞，**这个比例决定裁掉多少**。裁太狠会误伤正片 | 源有插播广告，播放器遇到空洞卡死 | 轻微 → `0.1`；严重 → `0.3`，**别超过 0.5** |
| **磁盘最少保留** | 切片在磁盘上**至少留这么久**才允许清理。回看和慢速播放器靠它兜底 | 网络差的观众播放卡顿、回看时切片已被删 | `300`（5 分钟） |
| **起播位置偏移** | 从直播边缘**往回退多少秒**开始播。填 `0` = 关闭。退得多更不容易卡，延迟也更大 | 首帧花屏、加载中黑屏 | `5`~`10` |

### 网络性能（高级，默认值适用大多数场景）

| 配置项 | 它做什么 | 什么时候动 | 例子 |
| --- | --- | --- | --- |
| **MPD 刷新间隔** | 两次拉取 MPD 的**间隔范围**，程序在区间内自适应。**区间给窄更贴合上游，也更容易被限流** | 默认值频繁被源站限流时才放宽 | 源站 429 → 放宽下限 |
| **并发下载** | **单个频道**同时拉几个片。**每个频道都会乘一遍**，频道多时容易把出网连接打满 | 频道多、连接数打满时调小 | 30 个频道时别超过 `2` |
| **片段超时** | 单个切片下载多久算失败。**太大会拖慢故障切换** | 上游很慢时太小会误判失败 | `10` |
| **MPD 超时** | 拉取 MPD 清单的超时。**有些源站生成清单本身就慢**，太小会误判成挂了 | 清单生成慢的源 | `10`~`15` |
| **重试次数** | 一个片最多重试几次。**频繁返回 403 的源可以调高** | 源频繁 403 / 网络抖动 | `3`~`5` |
| **重试间隔** | 两次重试之间等多久，**固定间隔** | 上游限流严格时调大 | `2`~`5` |
| **按需空闲停止** | **仅对「按需代理」频道生效**：没人看多久之后彻底停掉，下次有人访问时重新冷启动 | 用按需代理模式、想让空闲频道彻底释放资源 | `60` |
| **重建上限** | 看门狗连续重建几次仍不恢复，就判定该源当前不可用、转入冷却 | 源经常假死时 | `3`~`5` |
| **重建冷却** | 进入冷却后隔多久再自动试一次。**填 `0` = 永久放弃，只能手动重启** | 源挂了之后想让它隔多久自己再试 | `600`（10 分钟） |

### 特殊场景（高级参数）

| 配置项 | 它做什么 | 什么时候动 | 例子 |
| --- | --- | --- | --- |
| **MPD body 去重** | 上游返回的 MPD 内容没变时**跳过重新解析**，省 CPU | CPU 占用高时保持开启 | 保持开启 |
| **整片内存预算** | 自动档下，所有正在进行的整片发送加起来**最多占多少内存**。占满之后新请求走流式，占用降下去又自动恢复整片。填 `0` = **自动：可用内存的 1/8，封顶 512MB** | 内存不足时封顶下调 | `0`（自动）最省心 |
| **文件名混淆** | 把切片文件名换成**无规律的串**，防止照着规律盗链。**关掉只在抓包调试时有用** | 担心切片被推断盗链 | 保持开启 |
| **发片方式** | 两种都是读本地已落盘的切片，差别只在这一片的字节**要不要整块占住本进程内存**。见下方详解 | 带宽与人数需要权衡时 | 见下 |

#### 发片方式怎么选

| 选项 | 内存表现 | 适合 |
| --- | --- | --- |
| **整片** | 每个正在下载的连接**占住一整片（1~2 MB）** | **带宽大、人不多**。高带宽高延迟链路上更能顶满发送窗口 |
| **流式** | 每连接只留 **64 KB 缓冲**，内存与观看人数几乎无关 | **人多或内存紧** |

> **判断方法**：看仪表盘的「在线观众」。十来个人的小圈子用整片；几十上百人同时看就用流式。

## 上游源应该长什么样

```
http://upstream.example/dash/channel.mpd
```

**确认是不是 DASH**：

```bash
curl -sI http://upstream.example/dash/channel.mpd | grep -i content-type
# application/dash+xml  → 就是 DASH
```

也可以直接丢进 ffprobe：

```bash
ffprobe -v quiet -show_streams http://upstream.example/dash/channel.mpd
```

## 配置步骤

1. **分组管理** → 新建分组 → 工作模式选 **DASH（MPD → HLS 转封装）**
2. 新建频道，填上游 `.mpd` 地址、频道 ID、tvg-id
3. 源有 ClearKey 加密就填密钥，没有就留空
4. 想回看就填「回看保留时长」
5. 保存后复制订阅地址，导入播放器

> **M3U 批量导入时会自动识别**：`.mpd` 开头的频道自动归为 DASH 模式。所以导入 DASH 订阅不用手改。

## 代价

- **出网带宽** = 所有观众流量总和
- **CPU** = 转封装 + 清单解析，比 Proxy 重
- **内存** = 缓存的 MPD 与分片（用「整片内存预算」封顶）
- **配置项最多**，但默认值能覆盖大多数情况

---

## 排错

**播不了 / 花屏**
1. 源真的是 `.mpd` 吗？用 `curl -I` 看 Content-Type
2. 源的加密是不是 ClearKey？Widevine 需要额外处理
3. 频道的 ClearKey 密钥格式对不对（`kid:key`，32 位十六进制）

**起播慢**
- 先看「DASH 调优 → 播放体验 → 快速起播窗口」，但改之前记住默认值适配大多数源
- 检查上游 CDN 延迟

**卡顿**
- 先确认出口带宽跑满没有
- 再看「抗卡缓冲」和「磁盘最少保留」
- 并发下载别设太高，频道多时会打满连接

**字幕不显示 / 样式不对**
- 字幕设置**只对 DASH 频道生效**，确认分组模式没选错

**内存占用高**
- 「整片内存预算」保持自动（0），或手动封顶到 128MB
- 「发片方式」改用流式
