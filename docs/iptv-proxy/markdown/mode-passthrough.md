# 工作模式 · 直链（Passthrough）

> 模式标识：`passthrough`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：不代理、不改写、不加 token，原样把上游 URL 交给播放器。**服务器只负责记账。**

> 面板的官方说明：「原样导出别人的 URL,不经本服务;有 ClearKey 则按 MPD。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy
   ▲                    │
   │    返回的就是上游原始地址
   └────────────────────┘

✅ 订阅里写的地址 = 上游地址
```

与其他模式最大的区别：**Passthrough 的播放地址直接就是上游 URL**，不走 `/{分组}/{频道}` 这套路由。

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| **完全信任的源** | 你的官方源、自己的 CDN |
| 只想**统一管理频道清单** | 让这些频道出现在总订阅里，但流量完全不参与 |
| 源本身就是**公开直链** | 没有鉴权、没有加密、没有必要代理 |
| 给订阅**做一个占位条目** | 频道存在，但由别的途径播放 |

---

## 不适用场景

**任何需要控制的情况都不要用**：

- 需要隐藏源地址 → Passthrough 是把地址直接交出去
- 需要 Token 防盗链 → **Passthrough 不加 token**，这是它字面意思的一部分
- 需要缓存 / 回看 / 录制 → 都不经过本地拉流
- 源有鉴权或加密 → 完全暴露

> 它是唯一一个**默认不套用 Token** 的模式。别在需要防盗链的分组里用。

## 本模式的全部配置项

通用字段见 **[通用配置项详解](fields-common.md)**。Passthrough 的专属字段只有一个——ClearKey 密钥。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「Passthrough（直链）」 | — |
| 内容格式 / 预载切片上限 | **不显示**——直链不选格式，也不需要预载 |
| 网络配置（UA / 代理 / 请求头） | **会显示** |

---

### 频道级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **上游 URL** | **这个模式下最重要的字段**——它会原样出现在播放器的订阅里 | `http://cdn.example.com/live/cctv1.m3u8` |
| **ClearKey 解密密钥** | 见下方说明 | `kid_hex:key_hex` |
| **上游支持回看 / 回看天数** | 源站自己能处理回看时 | `7` |

#### 为什么 Passthrough 会有 ClearKey 密钥区

面板代码里写得很直白：

> 直链（有 key 即按 MPD 下发）也显示

也就是说，如果你在 Passthrough 分组里配了密钥，面板会**按 MPD 的形式把地址下发**。这是为「直链 + 加密」这个组合准备的。

**例子**：源是加密的 MPD，你在 Passthrough 频道里填上密钥，订阅里的地址就会带上对应的解密信息。

> **但要注意**：Passthrough 不做任何解密动作，它只是把密钥信息附在地址里。能不能解开取决于播放器自己。

---

### 不会出现的字段

| 字段 | 为什么没有 |
| --- | --- |
| 回看保留时长 / 最大磁盘占用 / 时间偏移 | 不录本地切片 |
| 预载配置 | 只有 Proxy 有 |
| MPD 裁剪保留秒数 | 不做 MPD 转换 |
| 源容器类型 | 那是 [Remux](mode-remux.md) 用的 |
| 上游缓存时长、跳转方式 | 那是 [Redirect](mode-redirect.md) 用的 |

---

## 配置步骤

1. **分组管理** → 新建分组 → 工作模式选 **Passthrough（直链）**
2. 新建频道，**上游 URL** 填完整的直链地址
3. tvg-id 照常填，EPG 匹配要用
4. 源加密的话填上 ClearKey 密钥
5. 保存后复制订阅地址

这个模式下上游 URL 是**唯一的关键字段**——它会原样出现在播放器里。

---

## 代价

- **带宽、CPU、内存占用全部为零**——服务器只存了一条记录
- 但相应地：无法统计真实观看情况之外的东西，也不提供任何转发价值

> 频道热度统计仍会记录播放列表的请求，这是 IP 管控和热度统计的监控对象。

---

## 排错

**订阅里的地址变成了上游原始地址**
- **这是设计如此**，不是 bug。Passthrough 的播放地址就是上游 URL

**加了 token 但还是被外链盗用**
- Passthrough **不套用 Token**。要防盗链必须用 [Proxy](mode-proxy.md) 配合 Token + 随机频道 ID

**源是加密的放不了**
- Passthrough 不做任何解密。加密源需要 [DASH](mode-dash.md)（ClearKey）或 [Proxy](mode-proxy.md)

**这个分组在总订阅里看不到**
- 检查分组的「访问范围」是不是设成了**隐藏**（不进总订阅）
