# 工作模式 · 反向代理（Proxy）

> 模式标识：`proxy`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：服务器替你拉流、缓存切片，再把切片转发给播放器。源地址对播放器不可见。

> 面板在模式选择框下方会显示这句官方说明：「清单与切片都经本服务转发并缓存，占带宽最高、最稳。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy  ──拉流──▶  上游源站
   ▲                    │
   └──回传切片───────────┘
                 （切片同时落盘缓存，第二次观看不再回源）
```

播放器只和你的服务器说话，从头到尾不知道源站在哪。这就是 Proxy 存在的理由。

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| 需要**隐藏源地址** | 频道链接被转发出去，源站地址不会暴露 |
| 需要**缓存提速** | 切片落盘，多人同时看同一频道时只有一次回源 |
| 源站**限制并发或按 IP 鉴权** | 所有请求都从你这一台服务器出去 |
| 想用**本地回看 / 定时录制** | Proxy 和 Remux 是仅有的两种支持本地切片的模式 |
| 想开 **Token 防盗链** | 播放地址带 token，未授权请求直接被挡 |

**不确定源是什么格式时的默认选择。** 兼容性和功能覆盖都是最完整的。

---

## 不适用场景

- 源站稳定且你不在意暴露地址 → [Redirect](mode-redirect.md) 更省你的带宽
- 源是 `.mpd`（MPEG-DASH）→ 用 [DASH](mode-dash.md)
- 源是 `.flv` / `.ts` / MMT 连续流 → 用 [Remux](mode-remux.md)，别让 Proxy 硬扛
- 服务器内存小 → Proxy 是最吃资源的模式，见下方「代价」

## 本模式的全部配置项

通用字段（分组 ID、tvg-id、上游 URL、网络配置等）见 **[通用配置项详解](fields-common.md)**，这里只列 Proxy 独有的。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「Proxy（反向代理）」 | — |
| **内容格式** | 上游给的是 `.m3u8` 还是 `.mpd`。**选错会解析失败** | 源是 `.m3u8` → 选 HLS |
| **MPD 裁剪保留秒数** | **只在「内容格式 = MPEG-DASH」时出现** | 见下方说明 |

> **Proxy 分组里找不到的字段**
>
> | 字段 | 原因 |
> | --- | --- |
> | **预载切片上限** | 当前版本这个控件整体已隐藏，任何模式下都不显示。预载只能在「系统设置 → 缓存配置」里全局设置 |
> | **源容器类型** | [Remux](mode-remux.md) 专用 |
> | **上游缓存时长、跳转方式** | [Redirect](mode-redirect.md) 专用 |

#### MPD 裁剪保留秒数

只在内容格式选 MPEG-DASH 时出现，含义是转换 MPD 时保留多长的时间窗口。

| 填法 | 效果 |
| --- | --- |
| `30` | 播放器能往回拖 30 秒 |
| 更大 | 回看范围更长，服务器占用也越大 |

> 追直播用不着往回拖，30 秒左右足够。

#### 网络配置

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **User-Agent** | 源报 403 或返回错误页时 | `Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0` |
| **代理类型** | 四选一：不使用代理 / HTTP 代理 / SOCKS5 / SOCKS5H（DNS 走代理） | 选了 SOCKS5H |
| **代理地址** | 上面选了代理才填，**不带协议前缀** | `127.0.0.1:7890` |
| **代理用户名** | 代理需要鉴权时；留空表示不认证 | — |
| **代理密码** | 同上 | — |
| **自定义请求头** | 点「＋ 添加请求头」逐条加，常用 Referer / Origin / Cookie | `Referer: https://example.com/` |

> **这组字段六种模式都会显示**——面板只对 5 个特定字段做了模式区分，网络配置不在其中。
>
> **User-Agent 有独立输入框**，别在「自定义请求头」里再填一次，两处都设会打架。

### 频道级

Proxy 频道上会显示两组区块：**推流 / 回看** 和 **网络配置**。

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **回看保留时长** | 想回看多久就填多少小时。**留空 = 不录** | 想留 24 小时 → 填 `24` |
| **最大磁盘占用** | 怕磁盘被撑爆就设上限。填 `0` = 不限，只按时长删 | 1TB 硬盘、5 个频道，想最多占 100GB → 填 `100` |
| **时间偏移** | **回看开头对不上节目时调它**，见下 | 放出来是上个节目结尾 → 调大 |

> **磁盘占用估算：一个 1080p 频道大约每小时 1~2 GB。**
> 算一下：留 24 小时 × 5 个频道 × 1.5 GB ≈ 180 GB。留 48 小时就翻倍。

#### 时间偏移到底怎么调

切片是按「录进来那一刻」打的时间戳，而直播本身有延迟，所以这个时间戳**比节目实际播出的时间要快**。

- 放出来的是**上一个节目的结尾** → 时间偏移**调大**
- 放出来的是**下一个节目的开头** → 时间偏移**调小**
- 填 `0` = 不偏移

**例子**：你按节目单点 20:00 的节目，播放出来是 19:55 那段的结尾，说明偏了 5 分钟，把偏移填 `300`（秒）。

---

#### 频道级的网络配置

和分组级同名，但**留空即继承分组设置**，适合个别源要求不同时单独覆盖。

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **User-Agent** | 这个源比别的源更严 | 单独一套 UA |
| **代理类型** | 选「继承分组设置」则用分组的 | 单独指定 |
| **代理地址 / 用户名 / 密码** | 同上 | — |
| **自定义请求头** | 与分组级的**合并**，同名以频道级为准 | 只补一个 `Referer` |

#### Proxy + MPD 时会多出的 ClearKey 密钥

分组的内容格式选 **MPEG-DASH** 时，频道上会额外出现 **ClearKey 解密密钥** 输入框。

**格式**：`kid_hex:key_hex`，多个密钥每行一对，KID 和 KEY 都是 32 位十六进制。无加密流留空。

```
a1b2c3d4e5f60718293a4b5c6d7e8f90:00112233445566778899aabbccddeeff
```

> 注意这和 [DASH 模式](mode-dash.md) 的区别：**内容格式选 MPD ≠ 工作模式选 DASH**。这里是 Proxy 模式 + MPD 内容（面板代码里叫「反代穿本服务」），只做反代不做转封装。

### 全局预载配置（系统设置 → 缓存配置）

**仅 Proxy 模式生效**。在播放器来要之前先把切片拉进缓存，起播更快。

| 字段 | 说明 | 建议值 |
| --- | --- | --- |
| **预载** | 开或关。**无人观看时仍产生上游流量** | 配置较低的服务器关闭。高带宽服务器开启 |
| **拉取并发** | 同时拉几片。越大填缓存越快，也越吃上游带宽和连接数 | `2`~`4` |
| **拉取超时** | 单片下载超过这个时间就放弃，避免一片卡住拖住整轮 | `10` |
| **HLS 预载** | 每次刷新清单后，最多提前下载几片。填 `0` = 整个列表都预载 | `3`~`5` |
| **MPD 预载** | 客户端取走一片之后，提前把后面几片拉好。填 `0` = 关闭，只按需取 | `2`~`4` |

> **预载不看观看人数。** 该功能只检查缓存是否足够。无人在看时仍会持续预载。对流量敏感的服务器应关闭该功能。

## 上游源应该长什么样

`.m3u8` 结尾的 HLS 播放列表。例如：

```
http://live.example.com/hls/cctv1.m3u8
```

在「分组管理 → 新建频道 → 上游 URL」填这个地址。

> 如果你的源是 `.mpd`、`.flv` 或 `.ts`，Proxy 不是对应模式，看
> [DASH](mode-dash.md) 或 [Remux](mode-remux.md)。

## 配置步骤

第一次用 IPTV Proxy 就按这个来，五分钟能播上。

### 1. 建分组

**分组管理** → 点右上角 `＋ 新建分组`：

| 字段 | 填什么 |
| --- | --- |
| 分组 ID | 英文小写，如 `live`。**它会出现在订阅地址里，之后改会让旧地址失效** |
| 显示名称 | 随便写，如「直播」 |
| 工作模式 | **Proxy（反向代理）** |
| 访问范围 | 公开 |
| 内容格式 | HLS (.m3u8) |
| 其余 | 先留空 |

保存。

### 2. 加频道

两种方式：

**方式 A · 手动加**（用来试单个源）

分组里点 `＋ 添加源`，填：频道 ID、频道名称、上游 URL。

**方式 B · 批量导入**（用来导整份订阅，推荐）

点顶部 **M3U 导入** → **粘贴订阅内容或上传 m3u 文件** → 频道模式选 **Proxy** → 导入策略选 **追加** → 开始导入。

> ⚠️ 这个弹窗**不能填订阅地址**，只接受文件或内容。地址要先下载成文件，或复制内容粘进去。
> 想直接填地址让它自动更新，用「订阅聚合」页。

详见 [订阅聚合入门](iptv.md)。

### 3. 补 tvg-id

导入后部分频道没有节目单。打开一个频道，把 **tvg-id** 填成节目单中的频道 id。

> 留空则用频道 ID，多数情况下匹配不上。

### 4. 复制订阅地址

分组列表右边点复制按钮，或直接拼：

```
http://你的IP:19899/live/playlist.m3u
```

### 5. 粘进播放器

TVBox / 影视仓 / TiviMate / Kodi 里填这个地址。

### 6. 播不了的话，按这个顺序查

1. **源本身能播吗** —— 把上游 URL 丢进 VLC。能播 = 源没问题，继续
2. **模式选对了吗** —— 源是 `.mpd` 要用 DASH，`.flv`/`.ts` 用 Remux
3. **UA / Referer 填了吗** —— 源报 403 或返回错误页就是缺这个。见上面「网络配置」
4. **Token 开了吗** —— 如果开了 Token，地址必须带 token 参数，用面板的「导出全部」而不是手工拼

### 7. 想回看的话

在频道的「回看保留时长」填小时数。**留空 = 不录**。

一个 1080p 频道每小时约 1~2 GB，先算算磁盘够不够。

## 代价

Proxy 是**最吃资源**的模式，因为流量真正经过你的服务器：

- **出网带宽** = 所有观众的流量总和
- **内存** = 缓存中的切片（可在系统设置里设上限）
- **CPU** = 转发与缓存维护；预载开启时更高

要省资源：预载关掉、缓存后端改 `memory` 并设上限、缓存目录设硬盘上限。

### 实测占用

v0.8.2 实测（1080p / 6.2 Mbps 直播流）：

| 并发观众 | CPU（占单核） | 容器内存 |
| --- | --- | --- |
| 1 个 | 0.86% | 71 MB |
| 2 个 | 1.31% | 77 MB |
| 5 个 | 1.07 – 1.51% | 89 – 117 MB |

**决定 CPU 的是码率，不是人数**；而**同一频道多人共享缓存**，5 人看同一个频道只占 0.51% 单核——比一个人还省。

真正的瓶颈是**带宽**：10 个观众看 6.2 Mbps 就是 62 Mbps 出网，比 CPU 重要一个数量级。

完整的换算方法、VPS 配置建议、内存控制开关、以及怎么自己测，见 **[资源占用实测](resource.md)**。

> 💡 流量成本敏感的话，Proxy 不一定是最好的选择——[Rewrite](mode-rewrite.md) 和 [Redirect](mode-redirect.md) 的出网接近于零。

## 排错

**播不了 / 花屏 / 一直转圈**
1. 源站地址能否直接在 VLC 里播？先排除源本身的问题
2. 网络配置里的 UA / Referer / Origin 是否填了？部分源站强制校验
3. 内容格式是不是选错了？源是 `.mpd` 就该用 [DASH](mode-dash.md)
4. 换 [Redirect](mode-redirect.md) 试一下——如果 Redirect 能播，说明源没问题，是代理链路上有环节不对

**能播但很卡**
- 预载开着？关掉试试
- 缓存上限是不是太小，一直在淘汰又重新拉
- 出口带宽是否已经跑满

**回看时间点不对**
- 先确认「系统设置 → 时区」配对了（中国大陆填 8）
- 再调频道的「时间偏移」，见上文

**磁盘撑爆**
- 给频道设「最大磁盘占用」上限，或调小「回看保留时长」

**想确认缓存有没有生效**
- 打开「缓存状态」页，看媒体片段数和磁盘占用是否在涨
