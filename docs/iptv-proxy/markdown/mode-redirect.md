# 工作模式 · 302 跳转（Redirect）

> 模式标识：`redirect`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：你的服务器不下发内容，只回一个 302，让播放器自己去源站拉流。**流量不经过你。**

> 面板的官方说明：「客户端按 302 直连上游,本服务仅做调度。带宽零开销,但客户端会暴露上游地址。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy  ──302──▶  源站地址
   ▲                    │
   └────播放器直接去源站拉流────┘

✅ 你的服务器只出了一次 302，之后完全不承载流量
```

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| **省带宽** | 流量直连源站，你的服务器只处理请求 |
| 源站**稳定** | 不需要代理层的容错 |
| 源是 **FLV / 直链源** | 面板的 M3U 导入里，Redirect 明确标注适合这类源 |
| 源靠 **IP 白名单** | 玩家的出口 IP 直连源站，注意得放得下 |

---

## 不适用场景

- **需要隐藏源地址** → 302 会把源站地址明明白白交出去，用 [Proxy](mode-proxy.md)
- 需要**缓存加速** → Redirect 不缓存
- 需要**本地回看 / 录制** → Redirect 不经过本地拉流，没有切片
- 源站**限制单 IP 并发** → 每人从自己的 IP 直连，源站并发压力上升

## 本模式的全部配置项

通用字段见 **[通用配置项详解](fields-common.md)**。Redirect 独有的是**跳转方式**和**上游缓存时长**两项。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「Redirect（302 跳转）」 | — |
| **跳转方式** | 决定跳转前做多少准备工作，见下方详解 | 绝大多数情况选「直接跳转」 |
| **上游缓存时长** | 解析出来的上游地址缓存多少秒 | 源地址带时效 token → 填比 token 有效期短的值 |

#### 跳转方式（Redirect 独有）

| 选项 | 它做了什么 | 什么时候选 |
| --- | --- | --- |
| **直接跳转（默认）** | 真正意义的 302：**脚本频道零回源直接跳**；静态地址只跟随重定向拿落地地址，**不下载播放列表** | **上游本来就是成品地址（绝大多数情况）**，换台更快 |
| **解析最佳画质** | 多下一次播放列表。若上游给的是 master 清单，就替客户端挑**码率最高的那一路**再跳 | 上游给的是多码率 master，你想让用户固定看最高画质 |

> **建议先用默认的「直接跳转」**。只有当你发现用户播到的是低码率、且上游确实是 master 清单时，才改成「解析最佳画质」。后者每次跳转要多一次回源。

#### 上游缓存时长

缓存的是「解析出来的上游地址」，不是媒体切片。

> **关键：带时效 token 的源，这里要填得比 token 有效期短。**
> 例子：源地址里的签名 300 秒就失效 → 上游缓存时长填 `240`，留 60 秒余量。填太长会拿到已过期的地址，表现为「过一会儿就开始 403」。

**默认值是 300 秒**（面板的输入框占位符）。

### 网络配置（分组级）

Redirect 分组会显示完整的网络配置，和 [Proxy](mode-proxy.md) 一样：

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **User-Agent** | 源报 403 或返回错误页时 | `Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0` |
| **代理类型 / 地址 / 用户名 / 密码** | 想隐藏服务器 IP 时 | `127.0.0.1:7890` |
| **自定义请求头** | 源要 Referer 才放行时 | `Referer: https://example.com/` |

> **这里有个反直觉的地方**：Redirect 的 302 响应**不经过你的服务器转发媒体**，但「跟随重定向拿落地地址」这一步会用到你设的 UA 和请求头。所以这两个字段在 Redirect 下**仍然有用**。

---

### 频道级

Redirect 不经过本地拉流，所以**没有推流 / 回看区块**。取而代之的是**源站回看**：

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **上游支持回看** | 源站自己能处理回看才选「是」，程序只把 `playseek` 追加到上游 URL | 源站支持时选「是」 |
| **回看天数** | 源站能回看多少天。**填大了播放器会拖到没有内容的时段** | 源站支持 7 天 → 填 `7` |

> **回看能力来自源站，不是你的服务器。** 这是 Redirect / Rewrite / Passthrough 三种模式共有的特点。

---

### 不会出现的字段

| 字段 | 为什么没有 |
| --- | --- |
| 回看保留时长 / 最大磁盘占用 / 时间偏移 | 不录本地切片 |
| 预载配置 | 只有 Proxy 有 |
| ClearKey 密钥 | 那是 [DASH](mode-dash.md) 用的 |
| MPD 裁剪保留秒数 | 只有 (Proxy 或 Rewrite) 且格式=MPD 时才出现 |
| 源容器类型 | 那是 [Remux](mode-remux.md) 用的 |

## 配置步骤

1. **分组管理** → 新建分组 → 工作模式选 **Redirect（302 跳转）**
2. 跳转方式选**直接跳转（默认）**
3. 上游缓存时长：源地址不带时效 token 就用默认 300；带 token 就填短一点
4. 新建频道，填上游 URL、频道 ID、tvg-id
5. 需要回看就开「上游支持回看」并填回看天数
6. 复制订阅地址，导入播放器

---

## 代价

- **你的出网带宽 ≈ 0**，这是它最大的价值
- 服务器只承担 302 响应，CPU 和内存占用都可以忽略
- **源站的并发压力由观众承担。** 观众集中访问同一源时，源站可能返回限流响应

---

## 排错

**播放器拿到订阅但播不了**
- 播放器是否支持 302 跟随？部分电视端播放器对跳转链支持不好
- 试试换成 [Proxy](mode-proxy.md) 看是不是播放器的问题

**跳过去了但源站拒绝**
- 源站可能按 IP 鉴权或限制地域。Redirect 让播放器用**自己的出口 IP** 直连。服务器上的 UA 和 Referer 只作用于获取落地地址这一步，**不影响后续的拉流请求**
- 这是切 Redirect 最常见的翻车点

**刚开机能播，过一会儿开始 403**
- 上游缓存时长填太长，缓存了已过期的地址。调短它

**想改跳转目标 / 加鉴权**
- Redirect 模式本身不适合加鉴权，那需要 [Proxy](mode-proxy.md)
