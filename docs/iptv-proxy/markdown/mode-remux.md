# 工作模式 · Remux 转封装

> 模式标识：`remux`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：把 FLV、TS、MMT 这类连续流转封装成 HLS，不解码画面。**注意：不需要解码，所以不吃 CPU。**

> 面板的官方说明：「连续流(FLV/裸TS/MMT-TLV)实时切片成 HLS。容器默认自动识别,识别失败可手动指定。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy  ──拉流──▶  上游（.flv / .ts / MMT）
   ▲                    │
   └──HLS 切片回传──────┘
              （只换封装，不解码 → CPU 开销极低）
```

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| 源是**连续流** | `.flv`、`.ts`、MMT 这些没有切片概念的流 |
| 源**不支持 HLS**，但播放器只吃 HLS | 转换封装后大多数播放器都能播 |
| 需要**本地回看 / 定时录制** | Remux 和 Proxy 是仅有的两种支持本地切片的模式 |

---

## 不适用场景

- 源已经是 `.m3u8` → 用 [Proxy](mode-proxy.md) 或 [Rewrite](mode-rewrite.md)，**不需要转封装这一步**
- 源是 `.mpd` → 用 [DASH](mode-dash.md)
- 只想隐藏源地址 → [Proxy](mode-proxy.md) 更通用

---

## Remux 与 Proxy 有什么区别

两者都能拉本地切片，但起点不同：

| | Proxy | Remux |
| --- | --- | --- |
| 源类型 | 已经是 HLS（`.m3u8`） | 连续流（FLV / TS / MMT） |
| 处理动作 | 转发 + 缓存 | 转封装成 HLS |
| CPU 占用 | 较高 | **低**（不解码） |
| 预载配置 | 有 | 无 |
| 内容格式可选 | 可选 HLS / MPD | **固定 HLS**（转封装输出一定是 HLS） |

> **一个历史坑**：早期面板只给 Proxy 显示推流/回看区块，Remux 频道明明能本地录切片，界面上却只能填一个对它无效的「源站回看天数」。v0.6.9 修正了这点——现在 Remux 分组同样会显示推流/回看区块。

## 本模式的全部配置项

通用字段见 **[通用配置项详解](fields-common.md)**。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「Remux（连续流 FLV/TS/MMT → HLS）」 | — |
| **源容器类型** | **Remux 独有**。默认「自动识别」即可，识别不准时再手填 | 源是 `.ts` 裸流 → 选 TS |

#### 源容器类型四个选项

| 选项 | 什么源选它 |
| --- | --- |
| **自动识别（推荐）** | 大多数情况都用这个 |
| **TS（HTTP-TS 裸流，最轻）** | 源是 MPEG-TS 传输流，`.ts` 结尾 |
| **FLV（HTTP-FLV）** | 源是 `.flv` 结尾 |
| **MMT-TLV（ARIB STD-B32 / BS4K）** | 日本 BS4K / ARIB 制式的直播源 |

> **什么时候需要手填**：自动识别把某些源判错了，表现是「能拉流但播不出来」。这时按源的真实格式选一下即可。

> **Remux 分组不显示「内容格式」**——转封装输出固定是 HLS，没有得选。
> **网络配置（UA / 代理 / 请求头）照常显示**，Remux 同样要回源，遇到源站要 Referer 或要鉴权时照样得填。

---

### 频道级

Remux 特有的区块与 Proxy 相同：**回看保留时长 / 最大磁盘占用 / 时间偏移**（面板上和网络配置放在一起）。

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **回看保留时长** | 想回看多久就填多少小时。留空 = 不录 | `24` |
| **最大磁盘占用** | 怕磁盘被撑爆就设上限，填 `0` = 不限 | `100` |
| **时间偏移** | 回看开头对不上节目时调 | 偏 5 分钟 → `300` |

> **磁盘占用估算：一个 1080p 频道大约每小时 1~2 GB。**
> **时间偏移怎么调**：放出来是上个节目结尾 → 调大；是下个节目开头 → 调小。

---

### 不会出现的字段

Remux 分组/频道上**看不到**这些，别找了：

| 字段 | 为什么没有 |
| --- | --- |
| 内容格式、MPD 裁剪保留秒数 | Remux 只输出 HLS |
| 网络配置（UA / 代理 / 请求头） | **会显示**，Remux 也要回源 |
| 预载配置 | 只有 Proxy 有预载 |
| ClearKey 密钥 | 那是 [DASH](mode-dash.md) 用的 |
| 源站回看 / 回看天数 | Remux 走本地切片，不用源站回看 |

## 上游源应该长什么样

以 `.flv`、`.ts` 结尾的连续流地址：

```
http://upstream.example/live/channel.flv
http://upstream.example/live/channel.ts
```

**怎么确认你的源是什么类型**：

```bash
ffprobe -v quiet -show_streams http://upstream.example/live/channel.flv
```

输出里的 `codec_type=video` 和容器信息能看出格式。

## 配置步骤

1. **分组管理** → 新建分组 → 工作模式选 **Remux**
2. 源容器类型保持「自动识别」
3. 新建频道，填上游 URL、频道 ID、tvg-id
4. 想回看就填「回看保留时长」
5. 复制该分组的订阅地址，导入播放器

---

## 代价

- **出网带宽** = 所有观众流量总和（和 Proxy 一样，流量经过服务器）
- **CPU** = 很低，这是 Remux 相对 Proxy 的主要优势
- **内存** = 缓存中的切片

---

## 排错

**播不了**
1. 上游 URL 真的是连续流吗？用上面的 `ffprobe` 确认
2. 「源容器类型」自动识别是不是判错了？按真实格式手选
3. 源站是不是强制校验 UA

**输出的是 HLS 但播放器不认**
- 少数播放器对转封装后的编码参数挑剔，换 [Proxy](mode-proxy.md) 对比一下是不是 Remux 的问题

**画面出来了但播着播着断**
- 检查源站本身的稳定性——转封装不会掩盖源流的断流
