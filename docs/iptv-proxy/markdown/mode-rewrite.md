# 工作模式 · URL 改写（Rewrite）

> 模式标识：`rewrite`　|　面板位置：分组管理 → 编辑分组 → 工作模式

**一句话**：只把 M3U8 播放列表里的相对地址改成绝对地址，**不转发任何内容**。最轻的一种模式。

> 面板的官方说明：「改写 M3U8/MPD 中的 URL 为绝对地址,切片由客户端直连上游。轻量代理。」

---

## 数据怎么流

```
播放器  ──请求──▶  IPTV Proxy  ──返回改写后的播放列表──▶  源站（只取一次清单）
   ▲                    │
   └────播放器自己去源站取切片────┘

✅ 切片不走你的服务器
```

服务器只做一件事：拿到 `.m3u8` 清单，把里面 `/live/seg1.ts` 这类相对路径改成 `http://源站/live/seg1.ts`，然后把清单交给播放器。**之后的切片流量完全在播放器和源站之间。**

---

## 使用条件

| 场景 | 说明 |
| --- | --- |
| 源的清单**用了相对路径** | 直接喂播放器会解析失败，改写成绝对地址就能播 |
| 需要**极轻量**的整理 | 服务器只出流量，不承载媒体 |
| 频道**数量很多**但流量分散 | 每个频道各拉各的，你的带宽压力小 |
| M3U **批量导入的默认落点** | 导入时「自动识别」把非 `.mpd` 的频道都归到这里 |

---

## 不适用场景

- 需要**隐藏源地址** → 改写后源站地址明明白白写在清单里
- 需要**缓存** → Rewrite 不缓存，每次播放都重新拉
- 源站**限制单 IP 并发** → 每个人都从自己的 IP 直连
- 需要**本地回看 / 录制** → 不经过本地拉流

> M3U 导入的默认策略就是 Rewrite：面板标注「Rewrite - 改写 M3U8 为绝对地址(HLS 通用)」。这是安全的默认值——不代理、不消耗带宽，先保证能播。

## 本模式的全部配置项

通用字段见 **[通用配置项详解](fields-common.md)**。Rewrite 的专属字段很少。

### 分组级

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **工作模式** | 固定选「Rewrite（URL 改写）」 | — |
| **内容格式** | 上游给的是 `.m3u8` 还是 `.mpd` | 源是 `.m3u8` → HLS |
| **MPD 裁剪保留秒数** | **只在「内容格式 = MPEG-DASH」时出现** | `30` |

#### 内容格式选 MPD 时会怎样

面板代码里对三种模式 + MPD 的组合有明确区分：

| 模式 + 内容格式 | 实际行为 |
| --- | --- |
| Proxy + MPD | 反代穿透本服务 |
| Rewrite + MPD | **直连 CDN** |
| Redirect + MPD | **直连 CDN** |

> 也就是说，Rewrite 和 Redirect 选 MPD 时并不转封装，只是把 MPD 地址原样给出去。**如果你真的需要 MPD→HLS 的转换，用 [DASH](mode-dash.md) 模式。**

#### 网络配置

Rewrite 分组**会显示**完整的网络配置（和 Proxy / Redirect 一样）：

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **User-Agent** | 取清单时被 403 就填 | `Mozilla/5.0 ... Chrome/120.0` |
| **代理类型 / 地址 / 用户名 / 密码** | 想隐藏服务器 IP 时 | `127.0.0.1:7890` |
| **自定义请求头** | 源要 Referer 才给清单时 | `Referer: https://example.com/` |

> **重要**：Rewrite 下你的服务器**只负责取清单**，请求头设置在这一步生效。播放器之后自己取切片，那部分不受你的设置影响——所以**源站要求 Referer 才能取切片时，Rewrite 会失败**，得换 [Proxy](mode-proxy.md)。

---

### 频道级

Rewrite 不经过本地拉流，所以**没有推流 / 回看区块**。取而代之的是**源站回看**：

| 字段 | 什么时候填 | 例子 |
| --- | --- | --- |
| **上游支持回看** | 源站自己能处理回看才选「是」 | 源站支持时选「是」 |
| **回看天数** | 源站能回看多少天。填大了播放器会拖到没有内容的时段 | `7` |

---

### 不会出现的字段

| 字段 | 为什么没有 |
| --- | --- |
| 回看保留时长 / 最大磁盘占用 / 时间偏移 | 不录本地切片 |
| 上游缓存时长、跳转方式 | 那是 [Redirect](mode-redirect.md) 独有的 |
| 源容器类型 | 那是 [Remux](mode-remux.md) 独有的 |
| 预载配置 | 只有 Proxy 有 |
| ClearKey 密钥 | 那是 [DASH](mode-dash.md) 用的 |

---

## 与 Redirect 的区别

两个都是「流量不走服务器」，区别在于**服务器出了多少力**：

| | Rewrite | [Redirect](mode-redirect.md) |
| --- | --- | --- |
| 服务器做什么 | 取清单、改写相对地址 | 回一个 302 |
| 清单谁去取 | 你的服务器取一次 | 播放器自己去取 |
| 适合源 | 清单用了相对路径的 HLS | 任意直链、`.flv`、`.ts` |
| 带宽 | 极小（只有清单） | 极小（只有 302） |

**简单判断**：源的 `.m3u8` 里写的是相对路径 → Rewrite；源本身要给直链（`.flv`、`.ts`）→ Redirect。

---

## 配置步骤

1. **分组管理** → 新建分组 → 工作模式选 **Rewrite（URL 改写）**
2. 新建频道，填上游 URL、频道 ID、tvg-id
3. 需要回看就开「上游支持回看」并填回看天数
4. 复制订阅地址，导入播放器

导入场景下大多数分组不需要手改——M3U 导入会自动把非 `.mpd` 的频道放进 Rewrite 分组。

---

## 代价

- **带宽接近零**，服务器只承担清单请求
- CPU 和内存占用都极低
- 但你**放弃了全部控制**：没有缓存、没有隐藏、没有录制、无法鉴权

---

## 排错

**改写后还是播不了**
1. 打开源站的 `.m3u8` 看一眼：如果它本来就是绝对地址，Rewrite 没有可改写的东西，问题在源站或播放器
2. 源是不是加密的？Rewrite 不处理加密，那种情况需要 [DASH](mode-dash.md) 或 [Proxy](mode-proxy.md)

**清单能取到但切片 404**
- 源站可能校验 Referer。**Rewrite 的请求头只作用于获取清单。** 播放器获取切片时不携带该设置。此类源站需要改用 [Proxy](mode-proxy.md)

**想改策略但怕破坏现有分组**
- 切换模式前先在「分组管理」用**导出全部**备份，模式切换后如果有问题可以导回
