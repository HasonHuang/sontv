#### M3U 批量导入

导入外部 M3U 订阅，支持选择文件或直接粘贴文本。

**频道模式**（决定导入后的处理方式）：

| 选项 | 说明 |
| --- | --- |
| 自动识别 | `.mpd` → DASH，其余 → Rewrite（**默认**） |
| Redirect | 302 跳转，适合 FLV / 直链源、脚本解析源 |
| Rewrite | 改写 M3U8 为绝对地址，HLS 通用方案 |
| Proxy | 完整反代 + 片段缓存转发 |
| DASH | MPD → HLS 实时代理，支持 ClearKey 解密 |
| Passthrough | 直链直通，不代理、不加 token |

**导入策略**：

| 策略 | 行为 |
| --- | --- |
| 追加 | 同名分组跳过，新分组追加（**安全**） |
| 合并 | 同名分组保留，新频道追加进去 |
| 覆盖 | 同名分组整体替换为新数据，其它分组保留 |

导入能力细节：
- `tvg-id` / `group-title` 等元数据全部保留，可在分组里手动微调
- UA / Referer / Origin 自动抓取（支持行内属性、`#EXTVLCOPT`、`#KODIPROP`、`#EXTHTTP`）
- ClearKey 加密自动填入 `license_key` 字段；Widevine 等其它加密类型需手动配置

#### 切片伪装

把切片伪装成图片，借 Cloudflare 默认图片缓存规则命中 CDN，**降低被滥用报告的风险**。

**它和反向代理是绑定的**：只有流量真正经过你的服务器时，程序才能把切片地址改写成图片后缀。
所以它只对**代理类模式**有意义——Proxy、Remux、DASH。
Rewrite / Redirect / Passthrough 的切片是上游直连的，改不了；订阅聚合来的频道更是完全不经过本服务。

| 选项 | 说明 | 建议 |
| --- | --- | --- |
| **切片伪装** | 把切片地址伪装成图片后缀，借 CDN 图片缓存规则提高命中率 | 前面有 CDN 时开 |
| **列表伪装** | 把 `.m3u8` / `.mpd` 也伪装成图片。面板说明：列表刷新频繁，收益大于切片伪装 | **开启** |
| **字幕 `.vtt` 伪装** | 字幕体积小，收益有限，**个别播放器会解析失败** | 关闭（面板标注推荐） |
| **主列表伪装** | 只影响多码率的 master 列表。**部分 iOS 播放器认不出伪装后的 master** | 关闭（面板标注推荐） |
| **伪装格式** | `jpg` / `png` / `gif` / `bmp` / `webp`，**多选，按切片稳定轮换** | 至少勾两个 |

##### 实测结果（v0.8.2，单码率 + 多码率两种源对比）

配置项在 `config.toml` 的 `[cache.disguise]` 段：

```toml
[cache.disguise]
enabled  = true                        # 切片伪装总开关
playlist = true                        # 列表伪装
subtitle = false                       # 字幕 .vtt 伪装
master   = false                       # 主列表伪装
formats  = ["jpg","png","gif","bmp","webp"]
```

**出厂默认就是 `enabled = true` + `playlist = true`**，不用手动开。

实测三层地址的变化（单码率源）：

| 层 | 伪装关闭 | 伪装开启 |
| --- | --- | --- |
| 播放入口（订阅里那条） | `http://host/组/频道.m3u8` | `http://host/组/频道.m3u8` ← **不变** |
| 清单里的切片 | `..._18e34b....ts` | `..._18e34b....webp` / `.png` / `.jpg` ← **变** |
| 文件名 | 哈希混淆 | 哈希混淆（独立设置，不受此开关影响） |

**结论与常见误解相反：**

- ✅ **切片后缀确实被改写**，在勾选的图片格式间**轮换**（实测依次出现 `.webp` → `.png` → `.jpg`）
- ❌ **播放入口地址永远是 `.m3u8`，不因开启伪装而改变**。分发出去的订阅地址**不会失效**，不需要重新发地址
- ⚠️ 面板源码注释里「入口地址要带扩展名（`.m3u8` / `.mpd` / 伪装时 `.txt`）」中的 `.txt` 分支，
  在实测中**只出现在多码率 master 的子流地址上**（`.../video/index.txt`），那是程序对多码率源做规范化
  转封装后自己生成的路径，**不是伪装开关的效果**——把它关掉，该地址依然是 `.txt`

补充观察：

- `playlist` / `master` / `subtitle` 三个开关在本次实测（单码率源 + 多码率源）中**没有观察到任何地址变化**，
  本次实测未观察到这三个开关对地址的影响。实测生效的设置是总开关 `enabled`
- 文件名混淆（`..._18e34bfbb515537d2bc7054e33d8ecfc`）与伪装无关，由 `cache.dash.obfuscate_filenames` 独立控制

##### 伪装到底改了什么（字节级结论）

**切片伪装不修改切片内容。** 程序只改写 URL 后缀和 Content-Type。

下载四种后缀的同一切片，前 32 字节逐字节相同。首字节是 `0x47`，这是 MPEG-TS 的同步字节。

每 188 字节都是 `0x47`。文件大小是 188 的整数倍。文件里没有 JPEG、PNG、WebP、BMP 或 fMP4 的特征字节。

把 `.png` 改名成 `.ts`，ffprobe 直接识别为 MPEG-TS，1920x1080 H.264 + AAC。

| 层 | 值 | 是否改变字节 |
| --- | --- | --- |
| URL 后缀 | `png` `jpg` `gif` `bmp` `webp` | 否 |
| Content-Type | `image/png` `image/jpeg` 等 | 否 |
| 路径形状 | 清单写成 `.txt`，切片平铺在频道目录下 | 否 |
| 切片载荷 | 原始 MPEG-TS，188 字节一个包 | 否 |

另外三个实测结论：

- **后缀不参与校验。** 清单写 `.png` 时，你请求 `.jpg` 也能拿到同一份字节，MD5 相同
- **轮换稳定且按频道独立。** 同一频道重复拉清单，扩展名序列不变；同一切片哈希在不同频道拿到不同后缀
- **`Cache-Control` 会切换。** 切片刚写入缓存时短暂返回 `public, max-age=300`，之后长期返回 `private, max-age=300`。公开窗口让 CDN 按图片规则收下对象，随后的 `private` 让 CDN 不再存储它。这层收益需要 CDN

切片还带有两项特征：

- 每个切片是自包含的 MPEG-TS，自带 PAT / PMT / SDT 和约 10 秒媒体
- 每个切片的第 0 个包携带 SDT，其描述符载荷是字符串 `lumberjack`（两次）。这是来源水印，与伪装无关

完整验证步骤、字节证据、扩展名分布表和 PID 表见 **[切片伪装的实现方式](disguise-analysis.md)**。

##### 怎么用

1. **默认就已经开着**，直接用即可
2. 要调整：系统设置 → 切片伪装 → 改开关与格式 → 保存
3. 切换伪装总开关会改变切片 URL。**已缓存切片的播放器需要重新加载播放列表**
4. 播放入口地址不受影响，分发出去的订阅继续有效

##### 前置条件

伪装的效果来自 CDN 对图片类文件的缓存规则。**没有 CDN 时收益很有限**——直连场景下程序改后缀也换不来缓存命中。

##### 出问题时

伪装会让排错变难：抓包看到的是 `.jpg`，播放器报「格式不支持」却看不出原因。

**排查时先把「切片伪装」和「列表伪装」关掉**，确认是伪装导致的还是源本身的问题。调通之后再开。

### 🔥 频道热度

### ⏰ 定时录制

为 Proxy / DASH 频道设置定时录制任务。

**运行机制**：
- 到达开始时间后系统自动启动该频道的流并录制，**无需提前手动开启推流或回看**
- 录制结束自动停止：若期间无人观看且频道非常驻，录制结束即回收；若有人观看或为常驻频道，保持运行
- 开始时间设为过去时，会尝试从已保留的回看历史补录
- 录制完成后切片自动合并为 MKV。支持多音轨。中断后仍可播放

> ⚠️ **必须安装 ffmpeg**，否则录制任务直接失败（用于封装 MKV，不转码）。
> 支持 Proxy（HLS，含多音轨/多字幕）和 DASH 两种模式频道。文件保存在 `cache/recordings/`。

安装：`apt install ffmpeg` · `brew install ffmpeg` · Windows 下载后加入 PATH。

#### 采集源与频道匹配

- **采集源**：顺序即优先级
- **频道匹配报告**：列出 `需要处理` / `映射失效` / `未匹配` / `手动源无数据` / `无节目` / `数据过期` / `正常` 各类数量
- **额外频道**：本机没有、但要带进输出的频道，可从源添加

### 🖼 台标管理

自己托管频道图标，M3U 的 `tvg-logo` 与 EPG 的 `icon` 都指向它。

| 功能 | 说明 |
| --- | --- |
| 上传台标 | 拖拽或点选，支持多选。png / jpg / webp / bmp / avif，浏览器内转码，**保留透明背景**；动图跳过转码 |
| 打开公开图库 | 从内置图库选 |
| 一键全部动态化 | 批量生成动态台标 |
| 全部还原静态 | 取消动态化 |
| 匹配到频道时一并设为台标 | 上传后自动匹配并应用 |

**生成动效**可选：斜向扫光（最百搭）、竖向扫光、来回扫光、光点掠过（最省体积）、边缘辉光、呼吸明暗（体积最大）。
**画质**三档：省流量 256px/5帧、均衡 384px/8帧、高清 512px/10帧。

列表可按 `全部` / `已被频道使用` / `未被使用` 筛选，并提示缺台标的频道数和仍用外部图床的频道数。

### 📥 订阅聚合

合并外部 M3U 订阅，按分组与关键词筛选。添加多个订阅源后可生成一份汇总订阅。

> ⚠️ **订阅聚合不做反向代理。** 它的频道在 `/playlist.m3u` 里输出**上游原始地址**，
> 播放器直连源站，不经过本服务——因此套不上工作模式、Token、缓存、录制，也隐藏不了源地址。
> （实测：手动添加的频道输出 `http://host/mygroup/HOY77.m3u8`，
> 订阅聚合来的频道输出 `https://上游域名/...`）
>
> **想让订阅走代理，用「分组管理 → M3U 导入」。** 导入的频道会变成你的分组和频道，获得代理地址。
> 多份订阅就各导入一次，会成为不同分组，总订阅自动合并。

- **顺序即优先级**
- 「保存订阅配置」保存全局设置
- 支持 `预览` 订阅内容的效果

### ⏪ 回看管理

Proxy / DASH 模式频道的推流与回看。

**启用步骤**：
1. 在「分组管理」编辑频道，Proxy 模式开启「推流模式 / 回看」，DASH 模式开启「开启回看」
2. 程序启动时自动开始推流，也可在此手动控制

**回看播放地址格式**（随「系统设置 → 回看格式」自动变化）：

```
http://host/<分组>/<频道>?playseek=<开始时间>-<结束时间>
```

时间格式 `20240101120000`（`yyyyMMddHHmmss`），**使用本地时间**——需在系统设置里配好时区偏移（UTC+8 填 `8`）。

切片存储在 `cache/livestream/`。

### 🎬 视频素材

把 404 / 错误重定向用的 MP4 转成本地 HLS，解决某些播放器不显示的问题。

内置 5 个占位资源：404 跳转、上游错误跳转、Token 失效跳转、IP 限流跳转、IP 封禁跳转。

> ⚠️ **需要 ffmpeg**。未安装时该项显示警告，且无法转换。
> 未转换的条目在重定向时仍发送原 MP4 URL。

### 📜 运行日志

实时查看系统运行日志，可按级别过滤（调试/信息/警告/错误）、控制显示条数（50/100/200/500/1000）、自动滚动。

日志同时写入 `iptv-proxy.log`，**最大 5MB**。

## 订阅与播放地址

| 用途 | 地址格式 |
| --- | --- |
| 分组订阅 | `http://host:19899/<分组ID>/playlist.m3u` |
| 频道播放 | `http://host:19899/<分组ID>/<频道ID>.m3u8`（扩展名见下） |
| 回看播放 | `http://host:19899/<分组>/<频道>?playseek=<开始>-<结束>` |
| EPG（XMLTV） | `http://host:19899/epg.xml` 或 `/epg.xml.gz` |
| 频道图标 | `http://host:19899/logo/<文件名>` |
| 自助解封 | `http://host:19899/unban` |
| 面板 | `http://host:19899/panel` |

> **播放地址的扩展名由后端计算**（`/status` 返回的 `entry_exts` 字段），随分组模式与伪装设置变化：HLS 模式是 `.m3u8`，MPEG-DASH 格式是 `.mpd`，**开启切片伪装时变成 `.txt`**。前端只查表不自行判断，保证面板显示的地址和 M3U 导出的始终一致。
>
> 路由本身**不带** `/index.m3u8` 这样的路径段（v0.5.1 起 `/:gid/:cid` 直接分发）。
>
> **Passthrough 模式是例外**：它的播放地址直接返回上游原始 URL，不走 `/{分组}/{频道}` 路由。
> 订阅地址在「分组管理」页每个分组旁点击复制按钮获取；「导出全部」可一次导出所有分组。
> 开启 Token 后，导出的地址会自动附加 token 参数；手工拼地址访问则需要自行带 token。

## 配置文件

面板里改的设置最终都写入 `/opt/iptv-proxy/config.toml`。文件只写最小必要项，其余走内置默认值——在面板改任何设置并保存后，后端会把完整配置回写。

```toml
[server]
bind = "[::]:19899"          # [::] 双栈；只要 IPv4 写 0.0.0.0:PORT
timezone_offset_hours = 8    # 中国大陆填 8，影响回看/EPG 时间
log_level = "info"           # trace / debug / info / warn / error

[panel]
enabled         = true
username        = "admin"
password_sha256 = "..."      # SHA-256，明文不落盘
session_ttl     = 86400      # 会话有效期（秒），默认 24 小时

[cache]
backend             = "disk"
disk_path           = "./cache"
m3u8_max_entries    = 500
segment_max_entries = 2000
disk_max_mb         = 0      # 0 = 不限

[auth]
token_enabled = false        # 建议公网部署时改为 true
```

配置文件有**热重载监视**，直接改文件也能生效（前提是热重载未被关闭）。

## 命令行运维

装好后脚本已软链到 `PATH`，可全局使用 `iptv-proxy`。

| 命令 | 作用 |
| --- | --- |
| `iptv-proxy` | 打开管理菜单 |
| `iptv-proxy update` | 更新二进制到最新版 |
| `iptv-proxy port <N>` | 改面板端口 |
| `iptv-proxy pass <密码> [账号]` | 改面板密码 / 账号（**忘密码也能改**，不用进面板） |
| `iptv-proxy restart` | 重启服务 |
| `iptv-proxy log` | 看运行日志 |
| `iptv-proxy url` | 打印面板地址 |
| `iptv-proxy uninstall` | 卸载 |

> 改端口和改密码都是直接改 `config.toml` 并重启服务，**改完旧登录会话失效**，需重新登录。

### 文件位置

```
/opt/iptv-proxy/
├── iptv-proxy          二进制
├── config.toml         配置（面板里改的东西都存这）
├── iptv-proxy.sh       安装/管理脚本
├── iptv-proxy.log      运行日志
└── cache/              切片缓存、台标、EPG 数据、录制文件
```

卸载时会问要不要一起删 `/opt/iptv-proxy`，选 `N` 就只停服务、保留数据，重装即恢复。

### Docker 部署（本环境）

本环境以容器方式运行，服务由容器内的启动脚本拉起：

```
容器名：iptv        镜像：alpine/curl:latest
端口映射：0.0.0.0:19899 -> 19899/tcp
工作目录：/opt/iptv-proxy
启动命令：./iptv-proxy config.toml
```

进程实际监听 `[::]:19899`。数据全在容器内 `/opt/iptv-proxy`，**容器内没有挂载卷——重建容器会丢失配置与缓存**，需要持久化请自行 `docker cp` 或改用 bind mount。
